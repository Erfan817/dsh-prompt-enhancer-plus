## 已知基线（开始前以源码核实）

1. `npm run desktop` 是浏览器本机服务；`desktop:electron` 才是 Electron。
2. Electron 与浏览器配置目录分离，不要合并或改名。
3. settings 没有 schemaVersion；载入异常时回退默认并提示，但之后保存可能覆盖原文件。
4. 现有 safeStorage 在不可用或 basic_text 时拒绝记住 Key；不得明文降级。
5. Key 不回传 renderer；endpoint 或协议变化时清旧 Key；原子写入成功后才更新内存。
6. 草稿/结果只在内存；桌面没有 DSH 的完整偏好学习库。
7. 现有测试包含 mock/源码检查，不等同于实际桌面端到端。

## 工作 B：配置版本化与非破坏性错误保护

请先给出简短实现思路，再直接在本任务范围内实施，无需扩展为框架。

### 必须满足

- 定义当前配置 schemaVersion，支持无版本旧配置的兼容读取；正常旧文件不因“读取”被自动改写。
- 已知版本正常读取；未知未来版本明确提示且不被默认值静默覆盖。
- 损坏 JSON、非法字段、超大文件、非预期读取错误明确区分；不以正常保存动作自动覆盖原文件。
- 允许用户显式恢复/重建的机制需要清楚的授权语义；若必须改 UI，只做最低必要提示/确认，不展开设置界面重设计。
- 安全存储不可用、密文不可解密时不崩溃、不泄密，不默默把原有密文删除；用明确动作区分“暂时不能用”和“用户决定清除/替换”。
- 保存失败保留旧磁盘文件和内存状态，后续重试可用；迁移重入结果确定。
- 保留现有 Key 格式、endpoint 校验、协议变化清 Key、原子写、串行保存和仅内存 Key 规则。
- 无明文凭据备份；如保留原文件或生成恢复副本，继续保护其中密文和权限，不输出其内容。
- 不统一两个配置目录，不改 Electron app 身份/userData 路径，不依赖浏览器和 Electron 同时写一个文件。
- 不声称解决跨进程写冲突，除非本任务确实实现并测试；通常将其明确列作当前分离目录的兼容边界即可。

### 需补的 mock/临时目录测试

- 无文件、正常无版本旧文件、当前版本文件、未知未来版本。
- 损坏 JSON、超大文件、非法 endpoint/model、读取权限等可控错误。
- 密文解密成功/失败、safeStorage 不可用/basic_text。
- 成功保存、失败后重试、连续保存、迁移重复执行。
- 保存失败不更新内存、不破坏旧文件；错误后保存不能静默覆盖受保护文件。
- endpoint/协议改变不继续带旧 Key；忘记 Key/仅内存使用行为保留。
- 公共 view/错误/测试日志不包含明文 Key。

针对平台特有文件系统错误，使用可注入最小 IO 或可靠测试替身；不要写脆弱的 Windows 权限模拟，也不要用源码字符串断言替代行为测试。

## 文件边界

优先只改 `desktop/settings.mjs` 和 `desktop/test-desktop.mjs`。若暴露结构化读取状态确实需要调用方适配，可最小修改 desktop 的初始化提示或保存处理，并解释必要性、补测试。

禁止修改：`prompt-core.js`、DSH `index.js/client.js`、Claude Code/Codex/VS Code 适配器、用户全局配置、模型凭据、已安装插件。不要新增依赖，除非先说明无法用现有工具实现的理由并获得同意。

不实现托盘、窗口样式、新快捷键、项目扫描、偏好学习、打包或自动更新。
