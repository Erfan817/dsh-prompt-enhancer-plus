# Prompt Spark 桌面优先产品规划

- 日期：2026-11-11
- 状态：用户已于 2026-11-11 认可产品规划；实施按任务分批推进。模型连接与费用仍待确认；本文不是已经实现的能力说明。
- 已确认方向：优先稳定、通用；桌面助手成为主入口，原生插件是可选增强。
- 本轮范围：只规划与编写实施任务，不修改业务代码、不部署、不发布、不调用真实模型。
- 首发目标：Windows 11 上独立使用；兼容 Claude Code、Codex、DSH 等软件的普通文本复制粘贴流程。

## 1. 产品定位

Prompt Spark 是一个发送前的提示词编辑助手，不是新的聊天客户端，不是新的 Agent harness，也不是宿主输入框的补丁。

核心闭环：用户复制草稿 → 打开 Prompt Spark → 自行粘贴 → 明确点击强化 → 审阅、修改或再次强化 → 明确点击复制 → 自行回到目标软件粘贴、发送。

成功标准：目标软件升级、未安装目标软件插件、目标软件未运行时，Prompt Spark 的基本编辑和强化流程仍然成立。模型网络或配置失败时，草稿和已有结果仍可编辑、复制。

“通用”先指不依赖目标应用的界面结构，而不是承诺首版适配全部操作系统、订阅或会话上下文。

## 1.1 已核对的代码基线

- 根 `package.json` 的 `desktop` 实际启动浏览器本机服务，`desktop:electron` 才是 Electron；不能把当前默认启动当作已经交付的独立桌面产品。
- Electron 已有单实例、最小 preload/IPC、固定 `CommandOrControl+Shift+Space` 热键和隐藏时取消请求；没有托盘，也没有可配置快捷键及正式打包脚本。
- 桌面已具备原稿/结果两个文本框、三档与内置方向；再次生成仍针对原稿，尚未具备针对手动编辑结果的连续强化。
- 已有独立 API 调用实现与默认 DeepSeek 配置，并非需要从零开发 provider；这不代表用户已经批准额外计费或真实调用。
- `settings.mjs` 已使用 safeStorage、原子写入和仅内存 Key，安全存储不可用时拒绝记住密钥；不应重复实现或降低这些保护。
- Electron 和浏览器模式目前使用不同配置目录；没有 schemaVersion。损坏配置回退默认后再保存可能覆盖原文件，迁移和错误保护需要优先处理。
- 桌面目前只提供内置方向和自定义方向，不包含 DSH 的完整人格管理/偏好学习库。首版不能把后者写成已具备功能。
- 现有桌面测试包含 mock 与源码断言，不能视为完整真实窗口操作测试。本轮未运行测试或启动应用。

## 2. 首版范围与明确不做

### 必须具备

- 独立桌面窗口、单实例、托盘显隐、明确退出；可配置的唤起快捷键。
- 原稿、结果两个独立的可编辑区域；强化结果不覆盖原稿。
- 简洁、标准、详细三档，复用现有共享强化规则，不同时改造输出格式。
- 可选的本次改写方向；可选择现有可复用人格，不另造一套模板系统。
- 首次强化针对当前原稿；“再次强化”明确针对当前结果全文和本次方向。
- 状态可见：未配置、就绪、生成中、取消、失败、成功；显示实际使用的连接与模型。
- 生成中能取消；失败不清空文本；过期请求不能覆盖新状态或用户编辑。
- 仅用户点击复制时写入剪贴板；正常手动粘贴，不自动读取剪贴板。
- 无模型连接也能打开窗口、输入、编辑和复制；配置缺失时明确提示。
- 明确模型数据去向与用量提示；提供连接设置和显式连接测试。
- Windows 独立分发试用包，不把安装 Node.js、PowerShell 或手动启动 HTTP 服务作为普通用户前置条件。

### 首版不做

- 不注入目标应用按钮，不抓取未发送草稿，不做 UI Automation 自动回填。
- 不模拟复制/粘贴快捷键，不自动发送，不监听键盘内容或剪贴板历史。
- 不复用或提取其他软件的凭据，不默认借用订阅或当前聊天模型。
- 不扫描项目、会话历史、全盘文件或本机 Skill 目录。
- 不新增后台学习、跨设备同步、自动更新、模型路由或多 Agent 工作流。
- 不增加目标应用专属入口；保留现有入口，不自动安装、卸载、启用或停用它们。
- 不在首版同步重构 DSH、Claude Code、Codex、VS Code 的界面或共享输出规范。

## 3. 交互约定

### 主窗口

顶部显示 Prompt Spark 标识、连接/模型状态、设置入口；主体为“原稿”和“强化结果”；底部集中放置三档、本次方向、强化/取消、再次强化、复制结果。

宽窗口原稿与结果并排；窄窗口上下排列，不能挤出横向滚动或遮挡操作。没有结果时给出简短操作说明，不自动填入演示草稿或发送请求。保留现有品牌，不照搬某个宿主的私有主题 token。

用户不需要选择“这是发给 Claude 还是 Codex”。目标软件通常与编辑器无关；若确实有特定要求，用户在草稿或方向里说明。

### 快捷键和生命周期

- 快捷键只唤起/聚焦窗口，不隐式读剪贴板或调用模型。
- 初始默认沿用现有 `Ctrl+Shift+Space`，允许改键，不另造冲突默认；`Ctrl+Alt+E` 可能被旧热键工具占用。注册失败必须可见，并允许改键或仅用托盘，不能循环抢占。
- 托盘不可用、快捷键冲突时，至少保留任务栏可恢复窗口；不得把窗口隐藏到无法唤回的状态。恢复窗口需校正到当前显示器可见范围。
- renderer 崩溃后提供明确重开路径；没有落盘的文本可能丢失，必须告知，不能宣称已自动恢复。
- 再次启动聚焦已有实例；最小化、隐藏后可恢复。
- 关闭按钮默认收起到托盘，首次明确告知；托盘“退出”才退出并取消请求。
- 默认不开机启动；系统关机或注销时正确退出，不阻止退出、不残留辅助进程。

### 请求与文本保护

- 请求开始时固定原文、方向、档位和连接的快照，并分配请求标识。
- 草稿是任务数据，不执行其内容；模型适配器不开放 shell、文件、浏览器或其他工具。
- 生成期间允许编辑；若结果区或相关输入已被用户改动，旧响应不能静默覆盖。提供非破坏性的完成结果保留/显式应用方式，或将请求判为过期并明确提示。
- 同时仅一个有效生成请求；取消、新请求、清空和退出使旧请求失效。
- 取消需要尽可能终止底层请求；仅忽略迟到结果不能称为已经停止服务端计费。
- 失败、空输出、超时、断网和取消都保留原稿、当前结果与方向。
- 无自动重试；用户主动重试也要清楚可能再次产生费用。
- 清空非空编辑内容需要确认；隐藏窗口不清空本次编辑。

## 4. 模型连接：先分层，不替用户决定付费方式

用户尚未确认接受额外 API 费用。规划不将“必须购买 API”或“能借用订阅”写成既定条件。

### 第一阶段

先用模拟适配器验证完整编辑流程，不联网、不消耗模型额度。核对现有桌面模型调用与配置，确认哪些可以安全复用。

### 可发布版本的选择门槛

发布带真实强化功能的桌面版前，必须明确一种可支持、可解释的真实连接：

1. **独立 API 连接**：若用户接受，先选一个具体服务验证，展示 endpoint/model 与数据发送说明。根据对应服务官方接口实现，不能把所有服务视为同一种协议。填写连接不等于同意后台测试；真实测试需用户主动触发并提示费用。
2. **宿主受支持连接**：仅在官方支持、授权清晰且端到端验证后提供。某个 CLI 能启动，不代表可以共享桌面订阅或当前会话。实验性的内部 app-server 调用不作为首版默认依赖。

若用户要求不产生额外费用、又没有可确认的受支持宿主连接，应如实说明：首版无法同时承诺独立通用和复用订阅；不能通过提取凭据或私有接口绕过。

### 内部约定

业务层只依赖小型连接适配接口，至少覆盖生成、取消、可理解的错误和可选用量；返回实际连接/模型信息。先适配现有实现，不从零建设通用 provider 框架。

如有真实网络请求，只发送本次草稿、方向、规则及明确选择的参考内容；不自动带上宿主聊天历史。不得静默切换供应商或模型。

## 5. 数据、隐私与兼容策略

- 默认本次草稿、预览和临时改写方向仅在内存中保留，退出清除；首次使用明确告知未保存内容的生命周期。
- 首版不新增持久化草稿历史；如旧实现存在自动保存，必须列出原行为和迁移方案，不能悄悄删除旧数据。
- 设置、人格等持久数据与临时编辑状态分开；保留当前已保存人格的兼容性。
- 已有 Key 不得随初始化/读取接口回传 renderer；用户在设置界面主动输入 Key 时会短暂存在输入控件中，提交后应清空。生成请求由主进程保管和使用凭据，禁止在页面长期缓存、URL、日志、错误消息或仓库中保存。
- 保留现有系统安全存储和不可用时仅内存使用的逻辑；不能改成明文或默默降级。
- 首版不合并 Electron 与浏览器配置目录、不改变 app 身份导致 userData 隐式迁移；显示品牌和数据目录身份分开处理。添加 schemaVersion 前明确旧文件和损坏文件的保护，失败不覆盖。若实际发现历史明文字段，单独设计清除/迁移，不假定当前配置是明文。
- 不可解密的 Key 提示用户重新输入，不尝试复制其他软件凭据或跨系统搬运密钥。
- 外部 API 的数据保留遵循实际服务政策；不宣称“本地应用等于数据完全不出本机”。
- 日志只记录状态、错误类别和耗时，不记录草稿、结果、凭据或完整响应体。
- 独立桌面主流程优先使用最小 preload/IPC 能力；旧本机 HTTP 接口是兼容入口，不应为新桌面首屏默认暴露额外监听。
- 旧 CLI、VS Code、浏览器兼容入口需要保留回归和明确启动方式，不能直接删除其服务或改变令牌、Host/Origin 校验。
- 不改日常 DSH 插件安装位置；现有稳定包继续可用，开发切分支不应改变已安装运行文件。

## 6. 实施顺序与 DeepSeek 任务

所有任务串行实施，避免多个写入者同时改 `desktop/renderer.js`、`main.mjs` 或共享规则。任务完成后先审查、验收，再进入下一项；不是一次性重写。

本计划没有假装已调用 DeepSeek。用户可将每项任务单独交给 DeepSeek，或在确认可用执行入口后再正式交接。真实任务应附带本文件和当前源码，不仅是一段脱离仓库的摘要。

### T0：基线与保护测试

目标：记录桌面现状，建立改造前基线。

- 核对桌面、配置、provider、旧 HTTP 客户端依赖与现有测试命令。
- 补齐或记录取消/迟到结果、配置迁移、秘密脱敏等现有覆盖。
- 不顺手修复其他平台，不更改强化规则。
- 交付：简短现状清单、测试结果、确切未覆盖项。

### T0.5：配置保护和版本化

目标：先保证旧设置可恢复，再让新界面保存新字段。

- 范围：`desktop/settings.mjs`、`test-desktop.mjs`，必要的初始化错误状态；不改全局配置。
- 引入版本化和非破坏性的坏文件处理；旧配置读取、未知版本、超大/损坏文件、不可解密 Key、保存失败、迁移重入均有明确结果。
- 沿用现有安全存储、endpoint/协议变化清 Key、原子写和保存成功才提交内存状态的保护。
- 不统一浏览器/Electron 目录、不改 app 身份；跨进程写入若不处理，需避免默认同时启动并明确兼容入口边界。
- 验收：已有安全配置原位可用；失败不覆盖原文件、不泄漏秘密、不发起网络请求。

### T1：稳定窗口外壳

目标：先让独立桌面入口可靠，无模型也可操作。

- 范围：`desktop/main.mjs`、`preload.cjs`、`launch.cjs` 及相关生命周期测试。
- 实现单实例、托盘、显隐、明确退出、可配置唤起快捷键和冲突处理。
- 桌面主流程不要求用户先开终端服务；不要默认启动旧外部热键工具。
- 验收：重复启动、关闭再开、最小化恢复、快捷键冲突、退出/注销无残留。

### T2：编辑闭环与请求状态

目标：完成不依赖宿主的文本编辑闭环，先用模拟连接验收。

- 范围：`desktop/index.html`、`renderer.js`、`styles.css`、必要的 IPC 调用和桌面测试。
- 原稿/结果分离、三档、改写方向、已有内置方向/自定义方向入口、连续强化、显式复制；不扩大为人格管理或偏好学习系统。
- 用独立且可测试的状态逻辑处理取消、失败、过期响应和手动编辑保护；不引入大型状态框架。
- 验收：原稿不被覆盖、再次强化使用手动编辑后的结果、失败和取消不丢数据、输入法换行正常。

### T3：真实连接与配置安全

前置：用户确认首个连接路线；未确认时 T1/T2 可继续，T3 不擅自调用真实模型。

- 范围：`desktop/provider.mjs`、`settings.mjs`、连接设置界面和相关测试。
- 抽取最小生成/取消接口，保留可复用 provider 逻辑；实现明确的实际模型展示、超时、错误与空输出处理。
- 保留已存在的安全凭据存储和 IPC 来源校验，配合 T0.5 的配置版本逻辑；只修复核实存在的缺口，不重新实现已满足的能力。若迁移涉及不可逆操作应先确认。
- 验收：未配置、无效配置、401/403、429、5xx、超时、断网、空输出均可恢复；敏感值不泄露。
- 真实调用测试独立于自动测试，得到用户授权后执行并记录模型、用量和范围。

### T4：Windows 交付与文档收敛

前置：T1–T3 可用且通过回归。

- 范围：桌面打包配置、根 `package.json` 的必要命令、README/中文摘要、相关 CI 和用户指南。
- 优先复用 Electron；不因产品转向改写成 Tauri、WebView 或另一套前端框架。
- 先产出独立可运行的 Windows 试用包；安装包和签名按实际条件决定，不承诺不存在的签名。
- Windows 未签名提示、更新/卸载、配置位置和隐私边界如实说明；不要求关闭系统安全功能。
- README 主路径改为桌面助手；DSH 原生插件作为可选增强，其他适配作为兼容/实验入口，保留原说明链接。
- 文档引用旧跨 harness 方案时说明定位变化，不篡改原方案的历史实施状态。
- 验收：无 Node.js/PowerShell 的干净 Windows 环境可运行；退出不残留；旧适配测试仍通过。

### 后续，不纳入首版

- 用户手动选择项目资料/Skill 文件，并显示实际发送内容、范围和限制。
- 用户明确开启的本地历史与恢复、删除能力。
- 经过可靠接口验证的宿主快捷入口。
- macOS / Linux、签名安装包与更新机制。

## 7. 每项任务可复用的 DeepSeek 执行约束

请只实施指定任务，不一次完成整份计划。开始前读取 `CONTRIBUTING.md`、本规划和相关源码，检查 `git status`；保护已有工作，不 reset、不 clean、不另行克隆。按照仓库规范使用短期功能分支；若已有本任务的功能分支则沿用，不在多个任务间盲目切换。

不得修改 DSH、Claude Code、Codex 或 VS Code 适配器来“顺便统一”；共享核心如非必要不改。不得读取宿主凭据、安装插件、改用户全局配置或操作其他软件的输入框。新增依赖需要说明必要性、锁定版本和打包影响。

自动测试必须使用模拟模型，不调用真实模型、不访问用户账户、不读写真实剪贴板；实际桌面/剪贴板/模型验证另行明确授权并记录。不得把 mock 通过称为真实桌面兼容通过。

完成时提供：改动文件、行为变化、测试命令与结果、未验证项、隐私/迁移影响、回滚方式。未获用户授权不提交、不推送、不创建 PR、不部署；若之后授权提交/PR，应遵循仓库要求及当前会话署名要求。

## 8. 验收矩阵

| 范围 | 自动化验收 | 真实环境验收 |
| --- | --- | --- |
| 编辑 | 原稿/结果分离、三档、连续强化、手动编辑保护 | 中文输入法、长文本、换行、多次修改 |
| 异步 | 取消、超时、迟到结果、新请求、关闭窗口 | 生成中隐藏再打开、断网恢复 |
| 剪贴板 | mock 证明只有显式操作写入、无自动读取 | 用户自备非敏感文本复制到不同应用，不发送 |
| 生命周期 | 单实例和显隐/退出状态测试 | 托盘、快捷键冲突、多屏/DPI、注销退出 |
| 模型 | 模拟成功/错误/空输出、明确实际模型 | 用户批准后真实调用，记录费用与数据路径 |
| 安全 | IPC 来源校验、存储迁移、脱敏、服务兼容回归 | 系统安全存储不可用时不明文降级 |
| 分发 | 包内容排除凭据、开发缓存和用户配置 | 无开发环境 Windows 安装/运行/退出 |
| 旧入口 | 相关现有测试和打包校验 | 未执行的宿主端到端检查明确标为未验证 |

发布检查不能只写“测试通过”。每条要注明环境、版本、实际操作、结果与未覆盖边界。产品可稳定运行不等于每次模型改写质量都有确定性保证，质量仍需人工样例检查。

## 9. 风险与回滚

- 最大产品风险：复制粘贴步骤被认为麻烦。先测试唤起、编辑、复制是否足够顺畅，不立刻用不稳定自动回填掩盖。
- 最大依赖风险：独立连接的配置与费用。T3 前作出决策；不能靠隐藏调用路径解决。
- 最大实现风险：异步结果覆盖用户编辑、配置迁移损坏、关闭窗口留下后台请求。优先测试，而不是先扩充功能。
- 改造以小步骤进行；保留已安装稳定插件和旧配置的安全恢复路径。回滚代码不保证能回滚数据，因此持久格式变更必须版本化并测试向后兼容。

## 10. 下一步决策

建议先批准 T0–T2 的实施范围，用模拟连接验证桌面编辑体验；同时确认 T3 首个真实连接的来源。没有真实连接时，交付物只能称为编辑流程原型，不能称为已完成的提示词强化正式版。
