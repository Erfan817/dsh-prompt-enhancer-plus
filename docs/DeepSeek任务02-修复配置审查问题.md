## 必须修复

### 1. 无法解密的已存 Key 不得因保存无关设置而消失

现状：配置有 `rememberKey/encryptedKey`，但 decrypt 失败时普通保存会省略 `encryptedKey`，从而覆写磁盘并丢失唯一密文。

期望：用户仅保存模型外的设置、且未明确清 Key/替换凭据时，保留原密文；不能尝试把未知密文搬到另一个 endpoint/provider，继续保持 endpoint 或协议切换清 Key 的保护。只有用户明确选择清除，或输入新 Key 并成功保存后，才替换/移除旧密文。错误提示须说明无法使用旧 Key、可重新输入或明确清除。

### 2. 安全存储暂不可用时，普通设置保存不得清除原密文

现状：`createSettingsStore` 对 browser 模式使用 `cipher === undefined`；已有加密配置在无安全存储的情况下会加载成 keyPresent=false。保存其他设置时不能把 `encryptedKey` 静默删掉。

期望：区分“安全存储当前不可用，但原密文须保留”与“用户主动忘记 Key”。保持 rememberKey 和原密文，直到安全存储可用时再解密；禁止明文降级。协议/endpoint 变化仍应按已有规则明确清除旧密文，UI 不得让用户误以为旧 Key 会用于新 endpoint。

### 3. 应用内有明确、安全的配置恢复路径

现状：损坏/非法/未来版本文件使正常保存抛 `settings-protected`，但 renderer 不发送 `reset`，没有恢复按钮；即使发 `reset: true`，现有 `save()` 在当前设置还没保存前没有 UI 可用的原始配置备份和风险说明。

期望：在 `settings` 的初始化状态中提供非敏感的恢复状态；当配置损坏、非法或不兼容时，设置对话框显示原文件保留且不可读取的明确提示，提供用户主动确认后才能以当前默认/表单值重建的路径。确认必须是可见且有上下文的用户操作，不接受 renderer 隐式附带 reset；重置前尽可能备份原文件到安全的唯一副本，不复制解密后的 Key，不覆盖既有备份。若未来版本配置不能安全备份/重建，阻止恢复并要求兼容版本处理。现有浏览器服务初始化和 `/api/settings` 接口不得因此失效。

### 4. 真正限制配置文件读取大小，避免 stat/read 竞态

现状：先 stat 检查大小再 readFile。文件或链接在两步间改变时，readFile 可能载入无界文件。

期望：在读取前/读取中实施有界读取，超过 `MAX_SETTINGS_BYTES` 立即停止并保护原文件。注意符号链接与文件被替换情况；按需要使用文件句柄、限制读取字节数并读取后再次校验文件信息。不允许先无界读入再按旧 stat 结果判定。

### 5. 测试必须真实触发保存阶段失败并在同一存储实例重试

现有 `not-a-file` 测试因初始化已保护而在写临时文件前失败，不能证明 rename/write 出错后保持内存/磁盘状态；当前 retry 使用全新路径与 store，也不能证明同一实例可恢复。

期望：用可注入的最小文件 IO seam 或可靠临时文件测试，单独模拟写临时文件失败、rename 失败，断言原文件未损坏、内存设置/Key 未提前提交、临时文件清理且同一个 store 后续成功重试。避免依赖不可靠的 Windows 权限模拟。

### 6. 未来版本配置的恢复提示和密钥策略一致

当前未来版本配置整份受保护是合理的默认，但显式重置路径可能丢失高版本字段和密文。

期望：未来版本默认只读、不降级、不尝试解密未知结构；任何重置前明确警告会丢弃兼容版本无法理解的数据，不允许含糊的“设置中重建”提示。优先提供备份后拒绝原位覆盖，或清楚的显式导出/清除策略。让用户可恢复使用，但不能以丢失唯一备份为代价。对此分支加入行为测试。

## 测试要求

新增/调整 mock 与临时目录测试，至少覆盖：
- 不可解密密文 + 保存其他设置时磁盘密文仍保留；显式清除和成功替换 Key 的行为。
- 安全存储不可用 + 普通保存时保留密文，且不能回传/使用明文。
- 恢复 UI 的 reset 确认信号只能来自明确操作；初始化失败状态与浏览器服务仍兼容。
- 超限和读取期间文件增长/替换时，实际最多读取上限附近字节，配置受保护，进程不会无界载入。
- write/rename 失败后旧文件与内存不变，临时文件清理，同一 store 重试成功。
- future schema 不被覆盖，UI 提示不会暗示可无损恢复。
- 保持 endpoint 变化清 Key、safeStorage basic_text 拒绝记住、无明文日志/磁盘等已有测试。

不要仅用源码包含字符串的断言声称 UI 行为已验证；对 DOM/UI 使用项目现有可运行测试策略或最小行为级测试。不能因测试实现反过来削弱安全语义。
