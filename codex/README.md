# Prompt Spark · Codex 独立提示词面板

在 Codex 桌面应用的原生侧边面板中输入草稿、选择详细度、强化并编辑结果。
点击“强化草稿”后，插件调用本机 Codex 后端的独立临时会话，结果直接返回
当前面板，不把强化请求发到当前聊天，也不生成新的聊天预览卡片。

面板支持再次强化当前预览、取消、复制和确认后放入输入框。需要 Node.js 22+
和已配置可用模型的 Codex 后端；Windows 会自动寻找桌面应用附带的模型组件。
无需启动桌面伴侣或本机 HTTP 服务，也无需另填一份 API Key；强化仍会使用
已有模型服务并消耗其用量。

这是 Codex 的原生插件面板。另有独立的 [Windows 悬浮组件](overlay/README.md)
可在输入框旁显示按钮并通过系统界面读取、替换草稿；安装本面板不会启动它。

## 安装与打开

本仓库附带 `prompt-spark-local` 本地 marketplace，入口指向 `codex/plugin`。
面向支持本地插件、MCP Apps 和界面入口扩展的 Codex 桌面版本。

1. 在 Codex 桌面应用中将**本仓库根目录**添加为项目并打开。该目录内应有
   `.agents/plugins/marketplace.json`，只打开父目录可能无法发现本地来源。
2. 按官方本地插件流程完整重启应用，在 **Plugins / 插件 → Prompt Spark
   本地来源**安装 **Prompt Spark · 提示词火花**。
3. 在对话右上角点击**新建标签页 → 更多工具 → 打开 Prompt Spark**，打开
   独立面板。这个入口无需先发送聊天消息。
4. 在面板内输入或粘贴草稿，选择档位，点击**强化草稿**。结果在同一面板
   出现后，可以编辑、再次强化、复制或放入输入框。

以上入口已在桌面应用 `26.1106.6628.0` 上实际操作验证。菜单名称和位置可能
随宿主版本变化；插件同时声明了对话面板和全局入口，具体由宿主展示。
也可以在聊天中要求“打开 Prompt Spark 提示词编辑面板”，由 `open_editor`
工具打开，但日常使用无需这一步聊天操作。

桌面应用从安装缓存加载插件副本。修改源码后，需要重新构建、更新安装并
重新打开面板；尚在运行的旧会话可能要新建会话或重启后才能加载新副本。
marketplace 文件本身只提供来源，不会自动安装或启用插件。

## 面板内强化

| 档位 | 输出 |
| --- | --- |
| 简洁 / concise | Task、Requirements，保留原意、减少赘述 |
| 标准 / standard（默认） | 有内容时增加 Acceptance criteria、Constraints |
| 详细 / detailed | 有依据时增加 Context、Failure cases |

规则来自共享 `prompt-core.js`。英文标签作为语义锚点，正文跟随原文语言；
省略空小节，不虚构数字、功能、项目事实或验收条件。草稿和强化结果的上限
均为 24000 字符。

“再次强化预览”使用当前可编辑预览和所选档位。失败或取消会保留已有文本；
生成期间手动修改预览时，晚到的结果不会覆盖编辑。后台默认 90 秒超时，
面板为这次工具调用保留 120 秒响应时间。服务不可用时可点击“重新检查”，
并在恢复后重试。

同一 MCP 连接一次只运行一个强化任务；共享该连接的多个面板不能同时强化。
遇到“正在强化”提示时，请等待当前任务完成或先取消。

独立后台使用**Codex 已有配置中的默认模型和供应商**。它不会自动跟随当前
聊天临时选择的型号，也不自动读取当前聊天历史、项目文件或本机 Skill。
需要这些资料时，请把相关内容写进草稿，或使用下面的聊天改写入口。

## 聊天改写入口

`prompt-spark:enhance` Skill 仍可处理直接发到聊天里的改写请求，例如：

```text
标准档强化下面的草稿，并显示可编辑预览：
帮我做一个导出 CSV 的功能，要能选择字段，使用 UTF-8，不修改现有数据结构。
```

这条入口由当前聊天模型改写，再通过 `render_preview` 展示结果，因此遵循
当前聊天的上下文和存储策略。可明确要求“结合当前项目 README”或指定本次
会话可用的 Skill 参考；它只参考这些内容，不执行其中的任务。项目资料每
文件最多 6000 字符、总计最多 8000 字符；Skill 最多三个，每个 6000 字符、
总计 12000 字符。明确要求“只返回文字”时不展示面板。

这些是聊天 Skill 的能力，不会自动应用到独立面板后台。

## 数据与界面边界

- 独立后台启动 `ephemeral` 临时会话，不继承当前聊天历史，也不向当前聊天
  添加强化消息。草稿会由已有模型配置对应的服务处理，遵循该服务的数据
  策略；“独立后台”不表示在本机离线运行模型。
- 插件通过 Codex 后端使用已有登录和模型配置，不读取或复制凭据文件。
  后台请求禁用 shell、MCP、插件、网页、计算机操作和项目说明等能力，
  只进行文字改写；遇到工具或授权请求会停止本次强化。
- 本地 MCP 进程使用 stdio，不监听 HTTP 端口。每次改写创建临时运行目录，
  请求结束后尝试清理。插件自身不保存草稿历史；Codex 与模型服务仍有各自
  的运行日志和数据策略。
- 原生面板无法读取未发送的输入框草稿，也不会替换已有草稿。宿主声明支持
  草稿插入时，“放入输入框”通过 `ui/message` 的 `send: false` 追加预览，
  由用户检查后手动发送；宿主拒绝时显示错误，不报告虚假的插入成功。
- 没有草稿插入能力时仍可复制；剪贴板受限时选中文本，供手动按 Ctrl+C
  （macOS：Cmd+C）复制。任何插入、复制都由用户点击触发。
- 模型指令不能保证每次输出都严格符合预期，使用前仍可在面板中审阅修改。

## 运行环境

Windows 默认从正在运行的 Codex 桌面组件及其托管安装目录寻找后端，不依赖
PATH 中另行安装的 Codex CLI。“检查本机强化组件”只检查组件是否存在，不会
调用模型，也不代表模型登录、额度或网络已验证通过。

可以给插件 MCP 进程设置以下环境变量；路径必须为绝对路径：

| 变量 | 用途 |
| --- | --- |
| `PROMPT_SPARK_CODEX_EXECUTABLE` | 指定可用的 Codex `app-server` 可执行文件；macOS / Linux 需要显式配置，尚未完成桌面界面实测 |
| `PROMPT_SPARK_RUNTIME_DIR` | 指定临时改写目录的根目录；默认是插件安装目录内的 `runtime/` |

若要求所有运行素材位于项目内，请将 `PROMPT_SPARK_RUNTIME_DIR` 指向该项目
中的可写目录。实际安装配置可通过 MCP server 的 `env` 字段传入；本机验收
使用本项目内 `codex/.host-check/native-panel-20261111/runtime/`。当前宿主
对环境配置存在缓存，本机部署另外将安装缓存中的 `runtime/` 目录联接到该
项目目录，已验证 `rewrite-*` 实际建立在项目内并在请求后清理。目录联接与
本机环境设置不会打进公开插件包；插件升级后需重新检查本机路径。

每次改写会在指定根目录下建立 `rewrite-*` 子目录，子进程的 TEMP、TMP、
TMPDIR 均指向该目录，完成后清理。临时目录不包含复制的登录凭据。

## 开发与验证

```sh
npm run codex:build
npm run codex:validate
npm run ci:package
```

`plugin/plugin.json` 是可编辑清单。构建脚本生成兼容清单、`.mcp.json`、图标、
许可证、共享规则副本和三档参考说明；不要单独修改生成副本。整个 `plugin/`
目录可独立安装，不依赖仓库外的本机脚本。当前 UI 资源为
`ui://prompt-spark/editor-v3.html`，继续接受旧 `editor-v2.html` 资源地址，避免
缓存了旧资源引用的宿主加载失败。

`codex:validate` 包含包内资源、MCP 传输与输入校验、面板交互和独立后端测试。
覆盖只在面板调用的工具、原生入口、当前预览再次强化、手动编辑保护、取消后
丢弃旧结果、能力缺失、服务失败与重试。自动化回归不调用真实模型。

2026-11-11 本机验证范围：

- Codex 桌面应用 `26.1106.6628.0`、自带后端 `0.167.0-alpha.4.1`，完成本地
  插件 `0.3.2` 安装和五个工具及面板资源加载。
- 在真实桌面窗口通过**新建标签页 → 更多工具 → 打开 Prompt Spark**打开
  原生侧边面板，点击强化调用真实配置的模型，约 11.1 秒后结果返回同一面板，
  包含 Task、Requirements 等内容。强化期间输入框不变，未向当前聊天发送
  消息；耗时是本次实测值，不代表固定延迟。
- 真实点击“放入输入框”后，预览成功进入原本为空的输入框，结果未发送。
  验证结束后已恢复输入框。该项验证了空输入框插入；宿主拒绝操作和缺少
  草稿能力等分支由自动化模拟测试覆盖。
- 真实点击“取消强化”后，已有预览与输入框内容保持不变，状态显示
  “强化已取消。”，面板恢复到可以再次强化的状态。

验证脚本、截图与临时目录存于项目内 `codex/.host-check/`，已被 Git 忽略并
排除在 npm 包之外。真实模型验证会产生正常模型用量；普通自动化检查不会。
