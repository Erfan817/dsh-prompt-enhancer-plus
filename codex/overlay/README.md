# Codex 输入框悬浮按钮（Windows）

这是独立的桌面伴随组件。通过 Windows UI Automation 定位 Codex 的主输入框，
在它左端上方显示“✦ 强化”和“预览”，与输入框左边缘对齐。点击强化后读取草稿、调用 Codex 配置的默认模型、显示
可编辑预览，由用户点击“替换原草稿”确认写回。不会模拟发送键。

交互参考本项目的 Claude Code 原生插件：独立预览入口、三档详细度、全宽编辑、
折叠原稿、显式复制、取消、撤销，以及过期预览保护。宿主适配仍独立维护。

## 启动与退出

先打开 Codex 桌面应用，然后双击本目录的 `start.vbs`。需要 Windows、
PowerShell 7 (`pwsh`) 和 Node.js 22+。不设置开机启动；一次只运行一个实例。
首次启动会在本目录 `runtime/` 下编译界面组件，通常需要数秒。

悬浮按钮右键 → **退出 Codex 悬浮按钮**。也可以运行本目录 `stop.ps1`；它会
核对运行标记对应的进程确实是此组件后再结束，不关闭 Codex 主程序。

开发或需要看到启动错误时，在仓库根目录运行：

```powershell
pwsh -NoProfile -File codex/overlay/launch.ps1
pwsh -NoProfile -File codex/overlay/launch.ps1 -Check
pwsh -NoProfile -File codex/overlay/launch.ps1 -Probe
```

## 使用与保护

- **强化 / 预览分开**：“强化”从当前输入框开始一次新请求；“预览”只打开
  当前进程内保留的结果，不调用模型。关闭后再开保留手动编辑和档位，退出组件
  后清除；没有持久化到磁盘。
- **编辑与连续强化**：回车只输入换行。原草稿默认收起，可以展开对照；
  “再次强化预览”基于当前编辑全文，失败或取消保留旧结果。
- **复制**：只在点击“复制”时写入剪贴板，不读取剪贴板或自动粘贴。
- **撤销替换**：成功写回后可以在预览窗口内撤销；仅当目标仍是同一窗口、
  同一输入框且文本等于刚写回的内容时允许。关闭预览、切换应用或返回 Codex
  后会禁用替换和撤销，以防切换聊天后误覆盖；结果仍可查看、编辑和复制。
- **关闭 / Esc / 取消**：中止进行中的请求，并拒绝它后来返回的结果。没有
  输出时也可以先开预览选择档位，再点击强化原草稿。
- 只有预览窗口确认显示后才隐藏悬浮入口。预览意外隐藏或最小化时，回到 Codex
  可再次点击按钮恢复；不会因为窗口对象仍存在而永久隐藏入口。

- Codex 在前台、未最小化且只有一个可识别的 ProseMirror 输入框时显示按钮。
  根据输入框实际位置定位，不固定屏幕坐标；按钮不抢键盘焦点。
- 只接受启动时确认的 Codex 完整程序路径。切换到其他应用时隐藏，预览回填
  失效；DSH 和 Claude 的路径不匹配。预览打开后回到 Codex 也会失效，避免
  切换聊天后写回另一个输入框。
- 不注册全局热键，不监听其他窗口键盘，不向其他软件注入界面。
  草稿在点击按钮时读取；预览打开期间会比较原文，发现更改则拒绝回填。
- 回填同时检查窗口、输入框运行标识和原文。写后读回核验，不自动发送。
  UI Automation 没有原子比较并交换能力，极短时间内的并发编辑仍需用户留意。
- 只有当前输入框纯文本参与强化，不处理附件，也不读取会话历史。
  内嵌提及或其他富文本元数据可能无法通过纯文本写回保留，请先审阅。

## 模型与资源

使用桌面版自带的 app-server 和用户已有的 Codex 登录/模型配置。不复制登录
凭据，不写全局配置。模型是**配置默认模型**，不保证等于某个聊天临时选择
的模型。强化仍消耗所选模型的用量。

每次强化建立独立临时会话，采用只读权限，并在该辅助进程中关闭 shell、
插件、MCP 服务器、hooks、浏览器、电脑操作和记忆等能力。改写规则取自
仓库的 `prompt-core.js`；不更改此共享核心。收到工具或授权请求则停止。
默认 90 秒超时，取消只终止本次辅助请求进程树，不关闭桌面版后台服务。
临时工作目录和运行标记在本目录 `runtime/`，不把用户草稿存入文件。
`runtime/overlay.log` 仅记录点击、显示、模型完成等状态及异常类型/调用栈，
不记录草稿、结果、账户或任意异常消息；日志大小限制为 128 KiB 左右。
宿主账户和服务端仍适用各自的日志/数据策略。

DSH、Claude Code 原生插件、通用桌面伴侣和全局热键的源码及配置不受修改；
悬浮组件启动时不会启动这些适配器。额外资源占用来自一个 Windows 界面进程，
强化时另起短期模型请求进程。退出悬浮组件即可停止这一入口。

## 已验证范围

2026-11-10，本机 Codex 桌面 26.1103.7773.0：

- 实际输入框定位，以及 UI Automation 同值写回（原草稿保持原样，无发送）；
- 默认模型的真实中文提示词改写；
- Codex 前台显示、DeepSeek Harness 前台隐藏；
- 原稿变化、窗口/输入框变化、已失效预览的保护条件；
- 真实 WinForms 控件的关闭再开、手动编辑与档位保留、复制/替换/撤销按钮状态；
- 撤销拒绝新草稿、原窗口变化，以及取消/新请求后的迟到结果保护；
- 编译、模型隔离参数及现有插件包检查。
- 修复点击后窗口隐藏的问题后，实际鼠标点击“强化”已验证到预览可见、真实
  模型完成且结果出现在编辑框；未替换或发送主输入框内容。
- 本机窗口显示、原生隐藏后恢复、最小化后恢复的回归检查。

后续检查已确认 Claude 和 DeepSeek Harness 前台时没有显示 Codex 悬浮窗口。
Codex 的前台切换在部分自动测试中被 Windows 阻止，测试会先确认窗口目标。
鼠标点击到预览生成已实测；WinForms 控件测试不等同于完整替换/撤销端到端测试。
没有声称完整桌面点击到替换流程、所有多显示器/DPI、附件和所有版本兼容
均已验证。宿主升级或可访问性树变化时会停止显示，需重新检查适配。

## 与 Claude Code 原生实现的差别

Claude 适配器有 `AbovePrompt`、`prompt.change/submit`、`session.model` 和
`model.complete` 等宿主接口，所以能使用当前聊天模型并及时发现提交/编辑。
Codex 悬浮组件只通过辅助功能接口识别窗口和纯文本；当前仍使用配置默认模型，
采用轮询和离开预览即失效的保守保护，不能保证捕捉轮询间隔内所有变化。
Claude 新版的 Skill 自动发现/手选参考、主任务运行状态事件未移植到悬浮组件。
